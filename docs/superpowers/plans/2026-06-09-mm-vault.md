# MM Liquidity Vault — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development or executing-plans to implement task-by-task. Steps use `- [ ]` checkboxes.

**Goal:** Build the `tai::mm_vault` Move module + manager runtime from the design spec (`docs/superpowers/specs/2026-06-08-mm-liquidity-vault-design.md`): a rate-bounded, revocable agentic MM fund — depositors get shares, a manager runs DeepBook MM over the pool through a price-bounded order path, NAV struck at settlement.

**Architecture:** A new Move module `tai::mm_vault` holding the vault state, a `VAULT_SHARE` coin, and a vault-owned DeepBook BalanceManager. The vault holds DeepBook's TradeCap; the manager places orders only through `manager_place_order` (price-band-checked). Pure-Tai accounting (vault/shares/NAV) has NO DeepBook dependency and is built + TDD'd first; the DeepBook-integration tasks come after a spike resolves the unknowns.

**Tech stack:** Sui Move 2024.beta (Tai package, in-place upgrade or new module), `@mysten/deepbook-v3` + `@mysten/sui` for the off-chain manager, vitest/sui-move-test.

**Status:** roadmap / post-audit. Mainnet deploy is gated on an external audit. Build order below keeps risk-bearing on-chain pieces last.
